# Durable local publication positions

`internal/publicationstate` is an unwired, local-only library for a caller-supplied publication selection, bounded record evidence, a locally accepted position and explicit first-use/replacement consent. It is not provider transport or authentication. The future caller must authenticate account/session/repository membership, current policy and the supplied repository observation before calling this package. The origin binding is a caller-provided association, not proof: this package requires exact `Observation.Origin` equality with its immutable store binding before caching, preparing or accepting. Spaces and public-repository bindings are separate profiles and are never inferred from one another.

The API is `Open(directory, binding)`, `OpenWithLimits(directory, binding, limits)`, `Close`, `Load`, `RecordObservation`, `Prepare`, `Accept` and bounded `History`. The directory must already exist, be absolute, owned by the current user, and have mode `0700`. Existing lock/database/WAL/SHM objects must already be owned private regular files at `0600`; unsafe objects and hard links where detectable refuse before lock acquisition or SQLite. No path is discovered, directory is created, or permission is repaired. A mode=ro SQLite probe reads committed WAL schema metadata before a read-write connection is opened. Foreign, v1, unknown or future schemas are not adopted. The lock is advisory on this local filesystem. Malicious same-user namespace replacement and stronger path-opening guarantees are out of scope.

The database holds one immutable account/backend/repository/vault binding and creation-time limits. Reopening with another binding or limits refuses. There is no reset, deletion, rebind, migration, installed default path or active executable integration. SQLite uses one connection, a mutex and lifetime flock, WAL, FULL synchronous mode, foreign keys and a bounded busy timeout.

`Prepare` and `Accept` revalidate every supplied record and decode the candidate payload bytes with `publication.DecodePayload`; a prior valid marker never substitutes for those bytes. Payload bytes are not persisted. A stored floor and audit remain readable without the payload, but preparing/accepting again requires valid supplied payload bytes. Accepted history retains candidate-first descending ancestry references and the raw records needed to verify them; unused supplied records affect only the framed supplied-set digest. The package does not claim complete repository membership, newest-position freshness, authorship, Spaces privacy, provider behavior, or authenticity.

The private compare-and-swap and consent digests use fixed ordered JSON wire DTOs, `[]byte` standard base64, UTF-8 validation, HTML escaping disabled and strict canonical round trips. They are internal store tokens, not a public or portable pin/confirmation protocol. `Floor.DatabaseID` and `Floor.Generation` must be consumed together as the invalidation pair `(DatabaseID, Generation)`: generation alone repeats after a new database is created. The pair is preparatory only; no v2 attempt blocking, abandonment, journal preservation, applied-base invalidation or re-establishment consumer exists. Spaces remains unwired, and this package does not enable service cutover.

The accepted event log is append-only and has a default terminal cap of 8192 events. There is no hidden eviction, reset or new-directory recovery that preserves continuity. Once event count or accepted logical-byte capacity is exhausted, new first-use/advance/replacement events refuse with `ErrLimit/accept/capacity`; `Load`, `History` and fully validated same-position no-ops remain available. The cap is finite and is not an unlimited lifetime or guaranteed replacement reserve. The independent record-only cache has default limits of 4096 records, 1024 observations and 16 MiB logical bytes. Cache saturation refuses only cache intake and never inserts cache rows during `Accept` or gates authoritative capacity. Accepted storage separately caps 16384 unique records and 128 MiB logical bytes.

Logical accounting is deterministic. A cache or accepted record is `raw record byte length + CID byte length + key byte length + 8` for sequence metadata. An observation is its canonical metadata byte length plus 32 bytes for its ID and 8 bytes of row metadata. An event is canonical event-body length, event digest length, stored old/new floor encodings, mode/reason/stop text lengths and 8 bytes for its revision key. Accepted logical bytes sum accepted record and event accounting. History counts each canonical event-body length plus digest/revision metadata and each unique raw-record reference's record accounting once per page; it returns the largest complete prefix that fits 16 MiB without skipping an event. These are logical row/read bounds, not physical SQLite/WAL/index size, disk-space guarantees, RSS bounds or power-loss guarantees.

`Accept` atomically commits accepted raw records, complete event evidence, active floor, revision/generation and the historical payload-validation marker. It has no fallible post-success-commit check. A commit error is returned as `ErrStorage/<stage>/commit_unknown`, the live store refuses further preparation/writes until `Load` verifies persisted floor/audit state or the store is closed and reopened, and callers must read back rather than infer rollback. A successful marker is historical validation evidence, not payload availability. `Open`, `Load`, `Prepare`, `Accept` and `History` currently scan and revalidate the complete bounded accepted audit before proceeding; a History page caps returned event/evidence bytes, not total verification work. `HistoryEvent.Trace` references resolve through the page-level `HistoryPage.Records`, which deduplicates raw records by CID and includes each returned event's held old-floor record when present. Missing/corrupt accepted evidence refuses the page without partial results.

Errors expose only closed class/stage/reason metadata through formatting and unwrap. No raw SQLite/filesystem causes are returned. The library stores sensitive position and repository/policy context; routine logs should use neither `Floor` nor `History` values.
